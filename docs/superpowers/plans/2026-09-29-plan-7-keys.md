# Plan 7 — ROG key and Fn+F5 bindings

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** the ROG key and Fn+F5 do something useful without G-Helper: Fn+F5 cycles the performance mode with an Omarchy OSD, the ROG key runs a configurable action (default: open the Armoury window once Plan 5 exists; until then an OSD saying so). armoury ships its own udev access rule for the keyboard device.

**Captured on device (2026-09-29):** every ASUS hotkey arrives on `ASUSTek Computer Inc. N-KEY Device` (event12), none on `Asus WMI hotkeys`. ROG key = `KEY_PROG1` (148), Fn+F5 = `KEY_PROG4` (203). The M-keys send `KEY_VOLUMEDOWN` 114 / `KEY_VOLUMEUP` 115 / `KEY_MICMUTE` 248, which Hyprland/Omarchy already handle — not rebound. No firmware Fn-lock attribute exists on this model; software Fn-lock (keyboard grab + uinput) is out of this plan pending the user's answer.

**Architecture:** `features/keys.rs` finds the N-KEY event node via `/sys/class/input/event*/device/name`, reads `input_event`s without grabbing (other consumers keep getting every key), maps 148/203 to `HotKey::{Rog, Fan}` and sends them to the daemon over a channel; it reopens the device after errors (resume, replug) with a backoff. The daemon acts only in active mode (G-Helper handles keys in observe mode). OSD via `omarchy-osd -m`.

## Global Constraints
- Never grab the keyboard. Only act on 148 and 203.
- Actions only in active mode.
- Config `[keys] rog = "…", fan = "…"`; actions: `none`, `open_window`, `cycle_mode`, `cycle_brightness`, `cycle_effect`, `command` (+ `rog_command`/`fan_command` string run via `sh -c`).

## Review Focus
1. Key pressed in observe mode → nothing happens (`keys_ignored_in_observe`).
2. Device disappears (suspend/replug) → reader reopens it; no busy loop (`reader_reopens_after_error` — backoff).
3. Held key auto-repeat (value 2) → one action per press (`repeat_is_ignored`).
4. Unknown action string in config → config error reported, default used.
5. `command` action with a failing command → logged, daemon keeps running.
